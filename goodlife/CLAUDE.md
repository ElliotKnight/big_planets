# GOODLIFE (formerly Progres)

A personal life-accomplishment / habit tracker web app. Single self-contained file: `index.html` (no build step, no framework, no server — just open it in a browser). Branded "Goodlife" (orange/yellow gradient title overlaid on the 3D panel); internal names and the localStorage key still use the old "progres" naming — do not rename the storage key, it would orphan users' saves.

## What it does

- **Layout**: the 3D world fills the entire viewport (`#fieldWrap` is fixed, fullscreen; page never scrolls). A **left sidebar** (📅 calendar / 🛣️ roads / ⬇ export / ⬆ import / 🗑 reset-everything, which confirms then clears localStorage and reloads) floats top-left; the 📅 button slides a **translucent calendar panel** (`.cal-panel`, blur + rgba backdrop so the island shows through) down from the top. The panel holds month nav + compact stats in its header and the habit grid in a `.cal-scroll` area sized to show the mood row + top ~3 goals — scroll for the rest (the mood row is rendered *first*, above the goal rows). The "Goodlife" brand sits bottom-left, orbit/zoom hint bottom-right.
- **Neon habit grid**: goals as rows (default: Gym, AWS Learning, Job Applications), days of the month as columns. Click a square to tick it — bouncy pop animation, shockwave ring, particle burst, and a Web Audio "plink" that rises in pitch when you chain clicks (combo system). Month navigation with ‹ › buttons; future dates are locked.
- **Goals are editable**: click name to rename (contenteditable), ✕ on row hover to delete (confirms first). Each goal row has a small **object chip** (`.goal-icon`, the `TYPE_META` emoji) — clicking it opens the object picker (`#objModal`, "goal" mode) to change the goal's default type/variant/dir. `+ Add goal` opens a **modal picker**: choose the object (skyscraper/tree/house/flowers/sheep/church/pond/bar/pool/playground/tennis/radiotower via `TYPE_META`), a style variant where available (skyscraper: Steel/Glass/Brick, tree: Oak/Pine/Cherry, house: Cottage/Seaside/Brick, flowers: Roses/Daisies/Tulips), a facing direction (N/E/S/W → `goal.dir` 0-3, applied as `rotation.y = dir·90°`), and optionally a tile on an 8×8 mini-map (writes `placements["id#0"]`, which is kept reserved even at 0 ticks — the prune rule spares instance #0).
- **Fresh-object flow**: when a tick makes `ticksFor(goal) % 7 === 1` (first-ever tick, or the previous instance just finished stage 7), the object picker opens in **"fresh" mode** — the choice is written to `state.overrides["goalId#idx"]` (per-instance `{type, variant, dir}`, so a finished skyscraper stays a skyscraper while the next object can differ). Its **"📍 Place on island"** button enters placement mode: the 3D layer raycasts tiles (`progres:placemode` event carries occupied cells; hovered tile glows green, red if taken), a click dispatches `progres:tileclick` back to the tracker which writes `placements[instKey]`, then a bottom **rotate bar** (↻ cycles the override's `dir`, ✓ done) appears. Esc or "keep auto spot" cancels placement.
- **Stats + streaks**: per-goal 🔥 streak badges (turn "hot" at 3+ days), and This month / All time / Best streak counters.
- **3D "Your World"**: a Three.js floating 8×8 grass island diorama at the bottom. Each goal grows a procedural low-poly object that **evolves one stage per tick, 7 stages max**, then overflows onto a new tile (spiralling outward from centre):
  - skyscraper (gains glowing floors with lit windows/residents → helipad at 7), tree (grows → sapling → blossoms; **stage 7 gets a nest with eggs**; `userData.perchY` marks where birds land), house (hut → chimney → windows → extension → 2nd floor → garden; also sets `perchY` at the roof apex), plant (duplicating flower patch — rose/daisy/tulip variants), animal (adult sheep grows; lambs are roaming agents), church (chapel → tower → spire → cross → stained glass → bell), pond (grows lilies/reeds/stones; ducks swim at 7), bar (sign → terrace → stools → string lights → rooftop neon), pool (water → rim → ladder → diving board → loungers → umbrella → slide; swimmers bob in rubber rings from stage 5), playground (sandpit → slide → swings → see-saw → roundabout → monkey bars → bunting; kids work the equipment from stage 3), tennis (court → lines → net → benches → umpire chair → floodlights → scoreboard; two players rally from stage 3), radiotower (red/white mast grows; hut → dish → antennas → side lights; blinking beacon from stage 3, broadcast rings at 7)
  - Default goals: Gym→skyscraper, AWS→tree, Job Apps→house; new goals are chosen in the add-goal modal.
  - **Selecting objects**: clicking a placed object in the 3D view raycasts it (`progres:objectclick` → tracker → `progres:selection` back) and shows **Move? / Rotate? / Cancel?** bubbles (`#objBubbles`, HTML pinned above the object by the render loop each frame). Move re-enters placement mode for that instance; Rotate opens the **d-pad** (`#rotateBar`: ▲▶▼◀ set facing N/E/S/W, arrow keys work too, ✓ done); Cancel deselects. Clicking empty ground deselects.
  - Camera: slow auto-orbit, drag to rotate, scroll to zoom. Spawn/evolve = elastic pop-in + neon ring FX.
  - Island tiles: flat rounded-box grass caps (two-tone green checkerboard) on inset dirt bases, tops flush at y=0. No decorative grass blades — tiles are bare.
- **Roads & paths**: the sidebar 🛣️ button (under 📅) opens a palette — **Cobble path / Dirt path / Road / Remove**. Picking one enters paint mode (same tile-raycast machinery as placement; hovered tile glows green, blocked red) and each click lays/erases that tile; stored in `state.roads` (`{cell: 0|1|2}`). Roads block object placement and auto-allocation (and vice-versa). The 3D layer rebuilds the road group when the roads JSON or house doors change. Roads render as **thin ribbons with green verges**: a centre pad (per-type width, `ROAD_STYLE[].w`) plus arms out to every connected edge (neighbouring road *or house*), each arm running exactly to the tile boundary so the two sides meet and **bridge the gap between tiles**. Asphalt gets a **kerbed sidewalk** wrapping it (corner squares + strips along arms + caps across armless sides — pieces abut, never overlap) plus centre dashes per arm; cobble = rounded setts in alternating shades along the ribbon; dirt = pebbles. Asphalt + cobble verges are dressed with **street furniture** (`makeLamp/makeBench/makeBin/makeBush`): lamps ~50% per arm on the kerb, benches ~24% (rotated to face the road), bins ~20%, bushes ~34% — all seeded by `roadRnd(cell…)` so layouts don't reshuffle on rebuilds. **A road adjacent to a house grows a matching-width stub from the shared edge to the front door** (slightly lower/narrower so it tucks under the arm without z-fighting).
- **Mood row**: first grid row (above the goals, so it never scrolls out of view) — click a day to cycle none → 😄 happy → 😐 ok → 😞 bad. **Weather = average of the latest 10 mood entries** (`moodScore()`: happy +1 / ok 0 / bad −1 → score −1…+1, null if none). Continuous blend: mild negative = dull overcast, rain fades in below ≈−0.25 (density/speed/opacity scale), lightning below ≈−0.55 (strike rate + flash strength scale to −1); positive = brighter/clearer with a sun orb; **score ≥ 0.7 = euphoria mode**: planets turn metallic disco balls pulsing/colour-cycling to a beat, and shooting stars become pink hearts.
- **Living world (agents)**: `syncAgents(items)` diffs a desired-agent map against live ones on every world event. Butterflies orbit trees (stage ≥2); **birds** perch on ~60% of stage-≥5 trees (stable per-key hash) and flit between tree crowns and house roofs (`perchY` spots; agent key includes the perch count so they re-learn); the adult sheep **stays put** and idles — stands looking around, lies down on folded legs, or grazes head-down (`sheepIdleAgent` poses the sheep model's `userData.head/legs/body`); lambs (animal stage ≥4) potter about their tile and occasionally walk to the tile edge, **jump the gap** to the next square, then bounce playfully or sit; **residents (stage-≥4 houses) can only travel on road tiles**: each outing BFSes the road network (`roadBFS`/`tracePath`) from the house to a tree (read), bar (drink) or playground/tennis (play), walking door → road waypoints → spot and back; with no reachable destination they stroll the paths, and with no adjacent road at all they just potter on the doorstep (resident agent key includes dest counts + `roadsHash` so they re-plan when paths are laid); ducks paddle circles on stage-7 ponds; swimmers bob in stage-≥5 pools; playground kids ride the swing/see-saw/roundabout (stage ≥3); tennis players rally with an arcing ball (stage ≥3); radio-tower beacons blink (stage ≥3, rings at 7). Pool/playground/tennis/beacon agents parent their meshes **into the built group** so they inherit tile position + facing. Skyscraper floors have lit window panes with tiny residents; stage 7 swaps the antenna for a helipad, and the tallest tower (stage ≥5) gets a helicopter that orbits the island, lands on the pad and takes off. Mood score ≥ 0.45 adds a rooftop party (bobbing dancers + colour-cycling lights) on the tallest tower. Sheep models face +x, so agent yaw is `atan2(-dz, dx)`; birds face +z (`atan2(dx, dz)`).
- **Space backdrop**: the island floats in space — additive starfield shell, nebula glow sprites, three alien planets (ringed teal, purple+moon, orange) placed *below* the horizon because the camera always looks down, and recycled shooting stars.

## Persistence

- Auto-saves to `localStorage` under key **`progres-data-v1`** on every change (toast confirms). Per-browser — same browser must be used to see progress.
- **Export / Import** buttons in the toolbar read/write a JSON backup (`progres-backup-YYYY-MM-DD.json`).

## Data model (`state` in localStorage)

```js
{
  goals: [{ id, name, type, variant, dir }],  // type ∈ skyscraper|tree|house|plant|animal|church|pond|bar|pool|playground|tennis|radiotower; variant 0-2; dir 0-3 (N/E/S/W)
  checks: { "goalId|YYYY-MM-DD": true },
  placements: { "goalId#instanceIdx": cellIndex0to63 },  // 3D tile allocations; "#0" survives 0 ticks (user-chosen spot)
  overrides: { "goalId#instanceIdx": { type, variant, dir } },  // per-instance choices from the fresh-object menu; pruned like placements
  roads: { "cellIndex": 0|1|2 },  // painted road/path tiles: 0 stone, 1 dirt, 2 asphalt
  moods: { "YYYY-MM-DD": "happy"|"ok"|"bad" }  // absent key = unmarked
}
```

`migrate()` backfills `type`/`variant`/`dir`/`placements`/`overrides`/`roads`/`moods` on old saves and imports.

## Architecture (all in index.html)

1. **CSS** — dark neon theme (`#07070f` bg, cyan/purple/pink gradients), per-goal cell colours via CSS custom props (`--c1/--c2/--glow`) from the JS `PALETTES` array.
2. **Classic script (IIFE)** — the tracker: state, localStorage, rendering (innerHTML table rebuild), Web Audio sounds, 2D canvas particles, streak/stat logic, mood row, and the **world model** (`computeWorld()` → items with `{key, type, color, cell, stage}`; `SPIRAL` orders the 64 cells outward from centre). Publishes to the 3D layer via `window.__progresWorld` + `progres:world` CustomEvent; the payload also carries `mood` (today's mood or null).
3. **ES module script** — Three.js scene (imported from jsdelivr CDN via importmap, three@0.160.0 + RoundedBoxGeometry from examples — **3D needs internet; the grid works offline**). Builds the island, lighting (warm sun + cyan/pink rim point lights, ACES tonemapping, soft shadows), the space backdrop, the weather system, the road layer, and the twelve 7-stage `BUILDERS`. Rebuilds an object when its stage, type or variant changes; otherwise just refreshes its position/rotation (manual placement can move objects). Disposes geometries/materials on rebuild. `setWeather(score)` rebuilds clouds and eases sun/ambient/exposure toward per-score targets each frame. Tile caps are raycast targets for placement mode (`progres:placemode` in → `progres:tileclick` out); anchored agent keys include the item's cell so agents follow moves.

## Conventions / gotchas

- Stage math: for a goal with N ticks, instances = `ceil(N/7)`; last instance stage = `N - 7*(instances-1)`; earlier instances are stage 7.
- Unticking devolves objects; deleting a goal prunes its checks and placements.
- Field caps at 64 objects (allocation just stops when full).
- The main script must run before the module (it does — module scripts are deferred), so `window.__progresWorld` is populated when the 3D layer initialises.
- Git repo (single `master` branch). No tests, no linting — verify by opening `index.html` in a browser.
